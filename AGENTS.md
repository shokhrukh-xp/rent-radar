# AGENTS.md — правила для ИИ-агентов (Codex, Claude и др.)

Ra'no (@rano_smart_bot) — ИИ-помощница в Telegram для поиска квартир в Ташкенте (аренда и покупка).
Работает на клиента: ищет объявления на сайтах и в каналах, пишет продавцам и маклерам, собирает ответы.
Владелец проекта — Шохрух (Xplorence). Идёт бета, есть живые пользователи.

## Как устроено

- **Python-бот** (`rent_radar.py` и модули) живёт в Docker-контейнере `rano` на сервере `sonar`.
  Каждые ~10 минут запускается проход: `git pull` из `main` → поиск → сообщения. **Всё, что попало в `main`,
  через 10 минут работает у людей.**
- **Cloudflare Worker** `rano-bot` (`worker/`) принимает обновления Telegram, ведёт интервью (Gemini), отдаёт
  мини-приложение `/app`, карту `/draw`, страницу `/about`, служебные `/svc/*`. Сам из GitHub **не**
  обновляется — его выкладывают `npx wrangler deploy` (с Mac владельца, см. «Выкладка»).
- Python и воркер говорят через очередь воркера (`/svc/updates`) и снимок состояния (`/svc/snapshot`).

| Файл | Что внутри |
|---|---|
| `rent_radar.py` | главный цикл, источники аренды, фильтры, карточки, очередь «по одной», команды |
| `concierge.py` | маклеры и продавцы: варианты, шортлист, уточнения, просмотры, анкета → фильтры |
| `sale_sources.py` | поиск квартир на покупку (Uybor, Realting, Joymee, Telegram…) |
| `geo.py`, `geo_districts.json` | место объявления: метка сайта, ориентир, метро; районы по границам OSM |
| `outreach.py` | Ra'no пишет продавцам со своего Telegram-аккаунта (лимиты, пауза, общий ответ) |
| `miniapp.py` | данные для мини-приложения (раздел `app` в снимке) и его действия |
| `tenants.py` | несколько пользователей: у каждого своя база `state/users/<chat>/` |
| `followup.py` | напоминания, вечерняя сводка, перепроверки по расписанию |
| `market.py`, `analyst.py` | цены рынка, оценка вариантов |
| `i18n.py`, `i18n_texts.py` | узбекский/русский/английский: `t("русский текст")` + каталог переводов |
| `worker/src/index.js` | воркер целиком; `about.js`, `draw.js`, `brand.js` (знак), `app.js` — собранное мини-приложение |
| `worker/app/app.html` | **исходник** мини-приложения → `python3 tools/build_app.py` → `worker/src/app.js` |
| `docs/brand/` | знак и надпись Ra'no, генератор `make_mark.py`, голос бренда `VOICE.md` |
| `tools/sim_e2e.py` | сквозная симуляция клиента (Telegram — заглушка) |

## Тесты — перед каждым коммитом

```sh
python3 test_offline.py                              # ~4 минуты, все блоки печатают «OK — …»; одна трасса «boom» — нарочно
cd worker && node --experimental-sqlite test/test.mjs
SIM_SKIP_LIVE=1 SIM_DIR=/tmp/sim python3 tools/sim_e2e.py . <radar.db> <sale.db>   # по желанию: пустые базы тоже годятся
```

Новое поведение — с тестом в `test_offline.py` или `worker/test/test.mjs`. Правили `worker/app/app.html` —
пересоберите `worker/src/app.js` (`python3 tools/build_app.py`) и закоммитьте оба файла.

## Как работать в репозитории

- Работайте в **своей ветке** и присылайте pull request. В `main` напрямую не пушьте: из `main` код сразу
  уходит людям, а Claude параллельно выкладывает исправления патчами в `main`.
- Коммиты небольшие, сообщение — что поменялось для пользователя и почему.
- Тексты для пользователей — по-русски через `t(...)` (перевод — в `i18n_texts.py`), голос — в `docs/brand/VOICE.md`.
  Ra'no — женский род («нашла», «спросила»); симуляция ловит мужской род о себе.
- Комментарии в коде — по-русски, коротко: зачем, а не что.

## Выкладка

1. Pull request смёрджен в `main` → Python-часть сама подтянется на сервер за ~10 минут.
2. Если менялось что-то в `worker/` — воркер нужно выложить отдельно, на Mac владельца:
   `cd ~/rent-radar-repo && git pull && cd worker && npx wrangler deploy`
   (или `sh deploy/mac_deploy.sh` — он выкладывает воркер, только если `worker/` поменялся).
3. Проверка: в логе сервера строка `Версия <коммит>`; у воркера — `Current Version ID`.

## Нельзя — без исключений

- **Секреты** (токен бота, ключи Gemini/Cloudflare, `SVC_KEY`, api_id/api_hash, сессии Telegram) не попадают в
  репозиторий, логи, тесты и сообщения. Они живут в Cloudflare secrets, в `.env` на сервере, в
  `/opt/rano/state/agent` и в `~/.rano_svc_key` на Mac. Агентам доступ к ним не нужен.
- **Данные людей** не коммитить: базы `*.db`, выгрузки, результаты симуляции — в них телефоны продавцов и
  переписка (`.gitignore` уже исключает `*.db`, `state/`, `tools/run/`).
- **Не писать реальным продавцам и маклерам** при разработке и тестах. Telegram в тестах — только заглушка.
- **Не обходить защиту сайтов:** капчи, скрытые телефоны (Uybor, Realting), антибот OLX/Birbir. OLX — только по
  ссылке, которую прислал сам пользователь.
- **Без массовых рассылок** с личных аккаунтов: Ra'no пишет продавцу только по нажатию клиента и в пределах
  лимитов `outreach.py`. Ra'no всегда представляется ИИ-помощником.
- **Nominatim и тайлы OSM:** свой User-Agent, кэш, не чаще 1 запроса в секунду.
- **Не удалять данные пользователей** и не менять их вручную на сервере.
- Письма, публикации, оплата (Telegram Stars, `PAYMENTS`) — только по решению владельца.

## Где смотреть, что происходит

- Логи бота: `ssh sonar 'docker logs --since 1h rano'` (доступ — у владельца).
- `/stats` в боте (владельцу) — воронка, оценки, причины пропусков.
- Статус беты и решения — в проекте владельца (документ `rano-beta-status`), спросите у него, если нужен контекст.
