## Что такое Ra'no (контекст, чтобы ты не переспрашивал)

Ra'no (узб. Raʼno — «прекрасная, изящная, как цветок раъно») — ИИ-ассистент по подбору
жилья. Клиент заполняет анкету (аренда / посуточно / покупка; квартира / дом / дача /
участок; город и районы; бюджет; класс жилья; этажи; календарь дат; состав жильцов;
животные; парковка). Ra'no составляет письмо, клиент одним тапом рассылает его маклерам
(риелторам). Маклеры присылают варианты **боту** (нельзя писать им первыми автоматически —
бан за спам). Ra'no принимает варианты, извлекает параметры, показывает клиенту по одному
с кнопками «В шортлист / Позже / Мимо», ведёт уточняющую переписку с маклером от своего
имени, строит **ценовой индекс только по данным маклеров** (листинги с порталов — часто
фейковые и с заниженной ценой), ведёт шортлист и запрос деталей.

Принципы, которые нельзя нарушать: Ra'no всегда представляется ИИ-ассистентом, не человеком;
имя клиента маклерам не раскрывается; никакой автоматической массовой рассылки с личных
аккаунтов; тексты клиенту — тёплые и без тёмных паттернов.

Модель монетизации (гипотеза основателя): без входной платы — показать 1–2 проверенных
варианта бесплатно, затем «маклеры прислали ещё N — доступно после оплаты». Клиент готов
платить за то, что за него ищут, ведут переписку и дают проверенные варианты. Комиссия с
маклеров тоже возможна.

Текущее состояние: работающий прототип на Telegram. Бот `@rano_smart_bot`; Mini App на
GitHub Pages (`https://shokhrukh-xp.github.io/rent-radar/`, фирменный стиль: гранатово-
золотая палитра, шрифт Fraunces, знак-бутон, ру/уз/en); сбор объявлений с OLX.uz, Uybor,
Telegram-каналов (Birbir 403 с GitHub IP); сборщик крутится в GitHub Actions 24/7 (бесплатно,
джоб живёт ~50 мин, cron `*/30`); SQLite-состояние коммитится в репо. Backend-логика
консьержа отделена от транспорта → можно навесить другие каналы. Токены — в GitHub Secrets.
Известные ограничения: нет реальной оплаты; нет API-бэкенда (Mini App без сервера, шортлист
внутри аппа невозможен); один пользователь (владелец); парсер вариантов от маклеров — regex,
Claude API ещё не подключён; нет напоминаний маклерам через 24ч; нет дедупа одной квартиры
от разных маклеров.

Мы уже знаем в общих чертах (проверь и углуби, не пересказывай):
WhatsApp Business API с июля 2025 тарифицируется за сообщение, есть окно 24ч, Flows для
анкет, in-chat платежи только в нескольких странах, строгие баны за неспрошенную рассылку.
Регуляторика ломает модель «арендатор платит за подбор»: UK Tenant Fees Act 2019 (+Renters'
Rights Act 2025), Германия Bestellerprinzip, Нидерланды — запрет комиссии с арендатора, США —
нужна лицензия риелтора и изменения после NAR settlement 2024.

## Что нужно исследовать (отвечай на КАЖДЫЙ вопрос отдельно и предметно)

### A. Рынок и конкуренты
1. Кто уже делает похожее (ИИ-консьерж по жилью, «поиск за вас», агрегаторы маклеров) —
   в Узбекистане, СНГ, Турции, MENA, Юго-Восточной Азии, Латинской Америке, Европе, США.
   Для каждого: модель монетизации, что именно они автоматизируют, оценки/трекшн, цена.
2. Чем Ra'no отличается и где её защищаемое преимущество (moat). Честно: где мы слабее.
3. Размер и структура рынка аренды/покупки в Ташкенте: доля сделок через маклеров, типичная
   комиссия, средняя длительность поиска, боли клиента (с источниками, а не догадками).

### B. Пользователь и путь клиента
4. Каким должен быть идеальный путь клиента от первого касания до сделки, с опорой на
   исследования UX (NN/G, Baymard, законы UX). Где в нашем текущем пути самые большие
   провалы и почему.
5. Как правильно устроить «момент оплаты» (free-first → paywall) без тёмных паттернов:
   примеры сервисов, конверсии, формулировки. Какая ценовая точка и формат (разовая /
   подписка / за вариант / успех-фи) реалистичны для Ташкента и для 3–4 следующих рынков.
6. Сторона маклеров: что им нужно, чтобы охотно присылать варианты; какие стимулы работают
   (комиссия, лиды, репутация, инструменты); как избежать спам-банов на всех каналах.

### C. Каналы доставки и «работать без перебоев на 100%»
7. Сравни как каналы: Telegram (бот + Mini App), WhatsApp Business API/Flows, собственный
   веб/PWA, нативные приложения, SMS/email. По каждому: стоимость на 1000 клиентов/мес,
   лимиты, что можно/нельзя автоматизировать, требования к верификации, риск блокировки.
8. Архитектура «ядро + адаптеры»: как спроектировать один бэкенд, который обслуживает
   Telegram, WhatsApp и веб одновременно, с очередями, вебхуками, идемпотентностью и
   ретраями. Конкретные стеки и хостинг с ценами (VPS / managed / serverless), SLA,
   мониторинг, алерты, бэкапы, ретенция данных. Дай **пошаговый план миграции** с текущего
   GitHub Actions + SQLite на прод-архитектуру, минимизируя простой.
9. Надёжность источников данных: как законно и устойчиво собирать объявления в Узбекистане
   и в целевых странах (официальные API, партнёрства, лицензии, лимиты, антибот). Список
   ключевых порталов по каждой стране-кандидату и статус их API/условий.
10. Использование LLM в контуре (Claude API): извлечение параметров из текста и фото
    маклера, ведение диалога, оценка «похожести на эталон». Стоимость на 1000 вариантов,
    защита от галлюцинаций, guardrails (не обещать от имени клиента, не раскрывать данные),
    логирование, оценка качества.
11. Платежи: провайдеры для Узбекистана (Payme, Click, Uzum и др.) и международные (Stripe,
    Paddle, local PSP) — комиссии, требования к юрлицу, вывод, возвраты, споры. Как встроить
    оплату в Telegram (Telegram Payments/Stars) и в веб.

### D. Юридика и данные по странам
12. Для КАЖДОЙ страны-кандидата (Узбекистан, Казахстан, Кыргызстан, Азербайджан, Грузия,
    Турция, ОАЭ, Саудовская Аравия, Индонезия, Вьетнам, Мексика, Колумбия, Польша, Сербия —
    плюс отдельно UK/DE/NL/US как «сложные»): можно ли брать плату с арендатора/покупателя;
    нужна ли лицензия для посредничества; правила персональных данных (согласия, хранение,
    трансграничная передача); правила рекламных/автоматических сообщений; налоги/юрлицо
    для нерезидента. Оцени каждую страну по «легко / с оговорками / нельзя» и предложи
    рабочую модель монетизации там, где «арендатор платит» запрещено.
13. Риски мошенничества и доверия: как верифицировать маклеров и объекты, что делают лидеры
    рынка (KYC, депозиты, рейтинги, страховки), что реально применимо на старте.

### E. Запуск и масштабирование
14. Пошаговый план запуска: сначала Ташкент (маховик предложение → варианты → довольные
    клиенты → сарафан), метрики успеха и пороги, при которых открывать следующий рынок.
    Затем 2–3 наиболее похожих рынка и почему именно они. Что нужно, чтобы запускать
    **несколько стран одновременно** (команда, локализация, юрлица, платежи, поддержка).
15. Юнит-экономика: CAC/LTV по каналам привлечения (Telegram-реклама, TikTok/Instagram,
    партнёрства с маклерами, реферальная программа), стоимость обслуживания одного клиента
    (LLM + сообщения + инфраструктура + поддержка), точка безубыточности.
16. Команда и операционка на первые 6 месяцев: минимальный состав, что отдавать
    подрядчикам, что автоматизировать.
